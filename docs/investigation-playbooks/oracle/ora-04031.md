# ORA-04031 Investigation Playbook

## Incident

**ORA-04031: Unable to allocate bytes of shared memory**

---

# 1. Objective

This playbook defines a structured investigation workflow for Oracle ORA-04031 incidents.

The objective is to identify the potential root cause by collecting and correlating evidence from:

* Oracle database memory
* Shared Pool
* Library Cache
* SQL and cursor activity
* Database sessions
* Operating system resources
* Oracle alert logs
* Historical incidents
* Recent changes

The investigation should avoid jumping directly to remediation, such as increasing the Shared Pool, without sufficient evidence.

---

# 2. Incident Context

Capture the following information from the incident:

| Evidence           | Description                                 |
| ------------------ | ------------------------------------------- |
| Database Name      | Oracle database where the incident occurred |
| Instance           | Affected Oracle instance                    |
| Timestamp          | Time of the incident                        |
| Error Code         | ORA-04031                                   |
| Allocation Size    | Requested memory allocation                 |
| Memory Pool        | Memory component reported in the error      |
| Process            | Process associated with the error           |
| Frequency          | Number of ORA-04031 occurrences             |
| Full Error Message | Complete error details                      |

---

# 3. Impact Assessment

Before detailed investigation, determine the business and database impact.

## Questions

* Is the database currently available?
* Is the database OPEN?
* Are application sessions failing?
* Is the ORA-04031 error recurring?
* Which application or service is affected?
* Is database performance degraded?
* Are new sessions able to connect?

Analyze the major SGA components:

* Shared Pool

* Java Pool
* Streams Pool

### Investigation Question

Which Oracle memory component is under pressure?

---

# 6. Shared Pool Investigation

Collect:

* Total Shared Pool memory
* Used memory
* Free memory
* Free memory percentage
* Largest free memory chunk

### Investigation Questions

* Is the Shared Pool under pressure?
* Is available memory low?
* Is the largest available memory chunk small?
* Is memory fragmentation present?

### Important Correlation

```text
Free Memory Available

BUT

Largest Free Chunk Small

+

ORA-04031

=

Possible Shared Pool Fragmentation
```

---

# 7. Library Cache Investigation

Collect:

* Gets
* Pins
* Reloads
* Invalidations

### Investigation Questions

* Is library cache activity unusually high?
* Are reloads increasing?
* Are invalidations occurring?
* Is hard parsing increasing?

---

# 8. Cursor Investigation

Collect:

* Open cursors
* Session cursor usage
* Duplicate SQL
* Child cursor count
* SQL version count

### Investigation Questions

* Is cursor usage increasing?
* Are applications generating excessive cursors?
* Are child cursors increasing?
* Is SQL being shared efficiently?

### Potential Pattern

```text
Application

↓

Poor Bind Variable Usage

↓

Hard Parsing

↓

Cursor Growth

↓

Shared Pool Pressure

↓

ORA-04031
```

---

# 9. Session and Workload Investigation

Collect:

* Active sessions
* Inactive sessions
* Session growth
* Application name
* Machine name
* Program name
* High parsing SQL
* Repeated SQL

### Investigation Questions

* Did session activity increase?
* Did a specific application generate excessive workload?
* Did a new workload begin before the incident?
* Are sessions generating excessive SQL parsing?

---

# 10. Operating System Investigation

Collect:

* Total physical memory
* Available memory
* Used memory
* Swap usage
* CPU utilization
* Load average
* Top memory-consuming processes
* Oracle process count

### Investigation Questions

* Is the operating system under memory pressure?
* Is swap usage increasing?
* Are Oracle processes consuming excessive memory?
* Is CPU pressure contributing to the incident?

---

# 11. Alert Log Investigation

Collect:

* ORA-04031 occurrences
* Error frequency
* Error timestamps
* Related ORA errors
* Instance events

Search for related errors:

* ORA-04030
* ORA-00600
* ORA-07445

### Investigation Questions

* Is ORA-04031 recurring?
* Did another error occur before ORA-04031?
* Is there a time-based pattern?

# 13. Root Cause Hypotheses

## Hypothesis 1: Shared Pool Exhaustion

### Evidence

* High Shared Pool usage
* Low available Shared Pool memory
* Frequent allocation failures

---

## Hypothesis 2: Shared Pool Fragmentation

### Evidence

* Free memory is available
* Largest free memory chunk is small
* ORA-04031 allocation failures occur

---

## Hypothesis 3: Excessive Hard Parsing

### Evidence

* High parse activity
* Increased Library Cache activity
* Cursor growth
* Shared Pool pressure

---

## Hypothesis 4: Cursor Explosion

### Evidence

* High open cursor usage
* High child cursor count
* Increasing session cursor usage

---

## Hypothesis 5: Application Workload Change

### Evidence

* Recent application deployment
* Increased workload
* Increased sessions
* Increased SQL parsing
* Incident occurred after the change

---

## Hypothesis 6: Incorrect Memory Configuration

### Evidence

* Shared Pool is consistently under pressure
* Normal workload
* Memory allocation configuration is insufficient

---

## Hypothesis 7: Operating System Memory Pressure

### Evidence

* Low available physical memory
* High swap usage
* High process memory consumption

---

# 14. Evidence Correlation Model

The investigation should not rely on a single metric.

Example:

```text
Shared Pool Usage: High

+

Library Cache Activity: High

+

Cursor Count: Increasing

+

OS Memory: Healthy

+

Recent Application Deployment

↓

High Probability:

Application SQL Behavior Causing Shared Pool Pressure
```

# 16. Safety Rules

The investigation phase should be read-only.

The platform must not automatically execute:

* ALTER SYSTEM
* Instance restart
* Database restart
* Shared Pool flush
* Production configuration changes

All remediation actions require DBA review and approval.
